# 🚀 Starlink 종합 시스템 아키텍처 및 배포 로드맵

> **작성일**: 2026년  
> **문서 목적**: 5G 고객 응대 방식(AWS 릴레이), 영업 및 디자인팀 온보딩 워크플로우, 그리고 하드웨어/소프트웨어 배포 전략을 아우르는 세세한 실행 계획 로드맵입니다.

---

## 1. 전체 시스템 아키텍처 개요

Starlink는 매장 내부의 초고속 로컬 처리와 중앙 클라우드(AWS)의 유연성을 결합한 **슬림 하이브리드(Slim Hybrid)** 모델을 채택합니다.

```mermaid
graph TD
    subgraph 🏪 가맹점 현장
        A[5G 스마트폰 고객] -->|QR 스캔| B[매장 테이블]
        C[매장 미니 PC / Ktor 로컬 서버] -->|실시간 KDS / POS| D[주방 태블릿]
    end

    subgraph ☁️ AWS 중앙 클라우드 허브
        E[AWS 릴레이 / 중앙 서버] -->|WebSocket / 터널링| C
        F[중앙 DB & 백오피스] -->|메뉴 동기화| C
    end

    subgraph 💼 본사 및 영업
        G[영업맨 앱] -->|Raw 메뉴 등록| F
        H[본사 디자인팀 어드민] -->|사진 매칭 & 승인| F
    end

    A -->|고정 도메인 릴레이| E
    E -->|패킷 중계| C
```

## 2. 5G 고객 접속 및 AWS 릴레이 서버 대응 방식

### 2.1 동작 메커니즘
1. **QR 코드 구조**: 손님이 매장 테이블에서 찍는 QR은 매장 사설 IP가 아닌 **AWS 릴레이 서버의 고정 도메인 및 매장 식별자**를 포함합니다 (`https://relay.starlink.co.kr/storeId=xxx&table=3`).
2. **릴레이 중계 (Gatekeeper)**:
   - 5G 스마트폰의 요청이 AWS 릴레이 서버로 도달합니다.
   - 릴레이 서버는 해당 매장의 미니 PC가 사전에 맺어둔 상시 터널링(WebSocket / Cloudflare Tunnel)을 통해 트래픽을 매장 로컬 서버로 안전하게 중계합니다.
3. **로컬 처리**: 매장 미니 PC(Ktor)가 0.1초 만에 주문을 처리하여 주방 KDS로 전파하므로 5G 통신 지연이나 외부 인터넷 음영 지역 이슈를 완벽히 극복합니다.

## 3. 영업 및 본사 디자인팀 메뉴 큐레이션 워크플로우

매장 온보딩부터 최종 서비스 개시까지의 데이터 라이프사이클입니다.

| 단계 | 주체 | 작업 내용 | 데이터 상태 (Status) |
| :--- | :--- | :--- | :--- |
| **1단계: 현장 미팅** | 영업맨 | 매장 방문 시 메뉴명, 가격, 기본 정보를 앱에 입력 | `DRAFT (초안)` |
| **2단계: 중앙 저장** | AWS 클라우드 | 영업맨이 입력한 Raw 데이터를 중앙 DB에 임시 저장 | `PENDING_DESIGN (심사 대기)` |
| **3단계: 디자인 큐레이션** | 본사 디자인팀 | 관리자 웹에서 Raw 메뉴에 고화질 음식 사진 매칭 및 UI 정제 | `APPROVED (승인 완료)` |
| **4단계: 최종 동기화** | 미니 PC 서버 | 매장 미니 PC가 부팅/갱신 시 중앙 클라우드에서 완성된 메뉴 다운로드 | `PUBLISHED (LIVE 서비스)` |

## 4. 하드웨어 및 소프트웨어 배포 전략 (Two-Track Deployment)

매장의 오픈 환경(자체 공급 vs 토스 포스/기존 PC)에 맞춘 이원화된 배포 전략을 운영합니다.

### 4.1 전략 A: 자체 공급형 미니 PC (Plug & Play)
* **적용 대상**: 소규모 초기 가맹점 또는 전용 하드웨어 패키지 선택 매장.
* **작업 내용**:
  - 본사에서 미니 PC를 일괄 사입하여 OS 최적화, Ktor 백엔드 및 자동 시작(Windows Service) 세팅을 공장 출고 전 완료.
  - 택배 발송 또는 영업맨 직접 지참. 현장에서는 **전원과 랜선만 꽂으면 즉시 작동**.

### 4.2 전략 B: 토스 포스 및 가맹점 기존 PC (Self-Service Installer)
* **적용 대상**: 이미 토스 POS나 기존 윈도우 PC를 사용 중인 가맹점.
* **작업 내용**:
  - 웹 다운로드 페이지(`.co.kr/download`) 제공.
  - 원클릭 설치 파일(`.exe`) 실행 시 자바 런타임, Ktor 백엔드, 백그라운드 서비스 등록, 매장 인증 코드(Store ID) 연동이 자동 진행되도록 인스톨러 빌드.

## 5. 단계별 세부 작업 로드맵 (Action Roadmap)

### 📌 Phase 1: 인프라 및 중앙 클라우드 백엔드 구축 (1~2주차)
- [ ] AWS EC2 및 고정 도메인(Route 53) 세팅
- [ ] AWS 릴레이 서버 및 웹소켓 패킷 중계 라우팅 구현 (`ServerMain.kt`)
- [ ] 본사 중앙 DB (메뉴, 매장, 영업 정보) 스키마 설계

### 📌 Phase 2: 영업 및 본사 디자인팀 백오피스 개발 (3주차)
- [ ] 영업맨용 모바일/웹 메뉴 등록 어드민 (Raw Data 입력 및 `DRAFT` 상태 관리)
- [ ] 본사 디자인팀용 메뉴 큐레이션 툴 (사진 매칭, UI 레이아웃 편집, `APPROVED` 승인 기능)

### 📌 Phase 3: 매장 미니 PC 로컬 서버 & 동기화 고도화 (4주차)
- [ ] Ktor 로컬 서버의 `Sync with Cloud` (중앙 메뉴 다운로드 및 로컬 SQLite 캐싱) 로직 구현
- [ ] 5G 릴레이 터널링(Cloudflare Tunnel / AWS Tunnel) 안정성 테스트 및 재연결(Reconnection) 로직 강화

### 📌 Phase 4: 배포 패키지 및 인스톨러 개발 (5주차)
- [ ] 자체 공급용 미니 PC 이미지 마스터링 (Factory Preset)
- [ ] 토스 포스 / 기존 PC용 원클릭 인스톨러(`.exe` / 자동 서비스 등록) 개발 및 필드 테스트
- [ ] 실전 5G 모바일 데이터 시뮬레이션 및 부하 테스트
