## 1. 개요 (Executive Summary)
Starlink(스타링크)는 매장 기존 POS PC의 가벼운 **로컬 백엔드(Store Local Server)**와 **중앙 클라우드 게이트웨이(Central Cloud Hub)**를 결합한 **슬림 하이브리드(Slim Hybrid) 운영 모델**을 채택합니다.

이 구조는 **운영비(OPEX) 최소화, 0.1초 실시간 처리, 법적/보안 리스크 0%**라는 3대 핵심 가치를 실현합니다.

---

## 2. 하이브리드 운영 구조 (Hybrid Architecture)

```
[ 🏪 매장 내부 (로컬 인프라 - 99% 처리) ]
┌──────────────────────────────────────────────────────────┐
│ 카운터 POS PC (Windows/Mac)                              │
│  ├── 1) 기존 POS 프로그램 (OKPOS, 배민포스 등) - 그대로 유지  │
│  └── 2) Starlink 로컬 서버 (Ktor Port 8888) - 백그라운드   │
└──────────────────────────┬───────────────────────────────┘
                           │ 📡 로컬 Wi-Fi (실시간 초고속 지연)
                           ▼
┌──────────────────────────────────────────────────────────┐
│ 주방 KDS 화면                                             │
│  ├── Option A: 주방 Wi-Fi 안드로이드 태블릿 (가장 추천)      │
│  └── Option B: 카운터 POS PC 듀얼 보조 모니터              │
└──────────────────────────────────────────────────────────┘

                           ▲
                           │ 🌐 PG 승인 Webhook 중계 (1% 처리)
                           ▼

[ ☁️ 스타링크 중앙 클라우드 (Central Cloud Hub) ]
 ├── 1) PG 결제 성공 Webhook 신호 중계 (Pure Gateway)
 ├── 2) 점주 SaaS 월 정액제(5만 원) 자동 수금 백오피스
 ├── 3) 카카오/네이버 1초 간편 로그인 카드 토큰 매핑
 └── 4) 전국 가맹점 포스 PC 원격 모니터링 & 자동 업데이트
```

## 3. 매장 로컬 인프라 운영 방식 (Store Local Operation)

### 3.1 기존 POS와의 완벽한 공존 (Co-existence)
- **독립 실행**: Ktor(JVM) 엔진은 수십 MB의 경량 메모리만 사용하므로 기존 포스기(OKPOS 등)와 한 PC에서 실행해도 화면 가림이나 성능 저하가 전혀 없습니다.
- **인터넷 단절 대응**: 매장 외부 인터넷이 순간 끊겨도, 로컬 Wi-Fi 망을 통해 손님의 QR 주문 및 주방 KDS 패킷 전파가 **100% 정상 작동**합니다.

### 3.2 주방 KDS 화면 구성
- **주방 무선 태블릿 (추천)**: 주방 벽면에 저가형 태블릿을 장착하고 `http://[포스IP]:8888/kitchen` 접속. 카운터 포스기를 왕복할 필요 없이 주방에서 직접 조리완료/서빙 상태 변경.
- **듀얼 모니터 (보조 화면)**: 포스 PC에 보조 모니터를 연결하여 주방/카운터 공동 확인.

## 4. 중앙 클라우드 허브 운영 방식 (Central Cloud Operations)

### 4.1 매출 정산 미개입 (Direct Settlement Model)
- **개입 제로**: 플랫폼은 점주의 매출 대금을 직접 보관하거나 정산하지 않습니다.
- **자금 흐름**: 손님 결제 대금 ➡️ PG사(토스/나이스) ➡️ **점주 사업자 계좌로 직접 입금** (D+2~3일).
- **법적 이점**: 전자금융업 등록 규제, 이행보증보험, 정산 에스크로 책임에서 완벽 탈피.

### 4.2 수수료 및 SaaS 정액 수금 구조
- **점주 구독료**: 매장당 **월 50,000원 고정 사용료** 부과.
- **자동 수금**: 가맹 시 등록된 점주 카드로 매월 자동 결제(Billing) 처리.

## 5. 결제 및 보안 시스템 (Payment & Security)

### 5.1 PG사 카드 토큰화 (Tokenization)
- 카드 원본 정보(카드번호, CVC)는 **오직 PG사 금융 보안 서버에만 저장**됩니다.
- 스타링크 시스템은 PG사로부터 암호화된 난수인 **`보안 토큰(Billing Key)`**만 전달받아 사용하므로, 서버 해킹 시에도 카드 정보 유출이 불가능합니다 (보안 책임 0%).

### 5.2 무설치 재방문 원터치 결제 (Zero-Install Re-visit UX)
- **`HTML5 localStorage` 활용**: 손님 브라우저의 전용 저장 공간에 카드 토큰이 암호화 저장됩니다.
- **재방문 경험**: 앱 설치 없이 동일 도메인 QR 스캔 시 **"💳 현대카드 **** 8829 [원터치 결제]"**가 즉시 활성화됩니다.
- **예외 복구**: 폰을 새로 바꾸거나 쿠키 삭제 시 "카카오 1초 로그인"을 통해 중앙 클라우드에서 토큰을 0.1초 만에 복구합니다.
